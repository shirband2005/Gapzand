# ربات مدیریت گروه — دانشگاه زند شیراز (نسخه‌ی پایتون)

ربات: **@Gapzandbot**
گروه: **@Gapzand**

این، پورت کامل و دقیق نسخه‌ی PHP همین ربات به پایتون است — تمام منوها، پنل‌ها، متن‌ها،
دستورات فارسی/انگلیسی و منطق داخلی بدون هیچ تغییری حفظ شده‌اند. فقط زبان و فریم‌ورک عوض شده:
به‌جای PHP + PDO از **Flask + PyMySQL** استفاده شده (وبهوک، دقیقاً مثل قبل).

سه روش دیپلوی پشتیبانی می‌شود:
- **Railway** (توصیه‌شده، ساده‌ترین حالت — همین پایین کامل توضیح داده شده) ⭐
- هاست اشتراکی بدون SSH با «Setup Python App» (پایین‌تر در همین فایل)
- VPS/سرور با SSH و Gunicorn دستی (پایین‌تر در همین فایل)

## 🚂 دیپلوی روی Railway

### گام ۱ — ساخت پروژه روی Railway
۱. وارد [railway.app](https://railway.app) شو و با گیت‌هاب لاگین کن.
۲. کد پروژه (همین پوشه‌ی `zandbot`) رو تو یه ریپوی گیت‌هاب آپلود کن (اگه گیت‌هاب بلد نیستی،
   ساده‌ترین راه: برو تو github.com یه ریپوی جدید بساز، دکمه‌ی "uploading an existing file"
   رو بزن و کل فایل‌های این پوشه رو (بعد از اکسترکت زیپ) بکش‌وبنداز اونجا).
۳. تو Railway روی **New Project** بزن → **Deploy from GitHub repo** → همون ریپو رو انتخاب کن.

### گام ۲ — افزودن دیتابیس MySQL
۱. داخل همون پروژه، روی **+ New** بزن → **Database** → **Add MySQL**.
۲. همین! Railway خودش یه دیتابیس می‌سازه و متغیرهای اتصال (`MYSQLHOST`, `MYSQLUSER`,
   `MYSQLPASSWORD`, `MYSQLDATABASE`, `MYSQLPORT`) رو خودکار در دسترس سرویس ربات می‌ذاره —
   نیازی نیست دستی چیزی وارد کنی (`config.py` از این نسخه به بعد خودش این متغیرها رو می‌خونه).

### گام ۳ — وارد کردن جدول‌ها تو دیتابیس
۱. روی همون سرویس MySQL که ساختی کلیک کن، برو تب **Data**.
۲. یه رابط شبیه phpMyAdmin می‌بینی؛ گزینه‌ی اجرای Query یا SQL رو پیدا کن.
۳. محتوای فایل `install/table.sql` رو کپی و اونجا پیست و اجرا کن.
   (روش جایگزین: تب **Connect** رو باز کن، یه دستور `mysql` با اطلاعات اتصال بهت می‌ده که
   می‌تونی با هر کلاینت MySQL دیگه‌ای مثل DBeaver/TablePlus هم وصل بشی و فایل رو ایمپورت کنی.)

### گام ۴ — تنظیم متغیرهای ربات
۱. روی سرویس ربات (نه دیتابیس) کلیک کن → تب **Variables**.
۲. این متغیرها رو اضافه کن (روی «+ New Variable»):

| نام متغیر | مقدار |
|---|---|
| `BOT_TOKEN` | توکن ربات از @BotFather (از قبل برات پرشده تو کد، ولی بهتره این‌جا هم صریح بذاری) |
| `BOT_USERNAME` | `Gapzandbot` |
| `OWNERS` | آیدی عددی تلگرام خودت (از @userinfobot بگیر) — اگه چندتا مالک داری با کاما جدا کن: `111,222` |
| `WEBHOOK_SECRET` | یه رشته‌ی دلخواه و محرمانه، مثلاً `zand-shiraz-secret-2026` یا هرچی خودت بخوای |

نیازی نیست متغیرهای دیتابیس رو دستی بذاری — چون هم‌پروژه‌ی MySQL ساختی، Railway خودش
`MYSQLHOST`/`MYSQLUSER`/... رو reference می‌کنه (این‌ها به‌صورت خودکار به سرویس تزریق می‌شن،
چون تو یک پروژه‌ی مشترک هستن).

۳. بعد از افزودن هر متغیر، Railway خودش یه دیپلوی جدید می‌زنه (طبیعیه).

### گام ۵ — گرفتن آدرس عمومی و ثبت وبهوک
۱. روی سرویس ربات → تب **Settings** → بخش **Networking** → دکمه‌ی **Generate Domain** رو بزن.
   یه آدرس شبیه `https://zandbot-production.up.railway.app` بهت می‌ده (با HTTPS رایگان و خودکار).
۲. حالا (دقیقاً مثل قبل) این لینک رو با مقادیر خودت پر کن و تو مرورگر باز کن:
```
https://api.telegram.org/bot<BOT_TOKEN>/setWebhook?url=<آدرس Railway>/&secret_token=<WEBHOOK_SECRET>
```
مثال:
```
https://api.telegram.org/bot8680723464:AAGca2_GEFJhHAOHXvCjUo_5A1PXop7tEEc/setWebhook?url=https://zandbot-production.up.railway.app/&secret_token=zand-shiraz-secret-2026
```
۳. اگه `{"ok":true,"result":true,"description":"Webhook was set"}` دیدی، تمومه.

### گام ۶ — تست
ربات رو به یه گروه اضافه کن، ادمینش کن، بنویس «راهنما» — باید جواب بده.

### نکات مخصوص Railway
- **کرون‌جاب لازم نیست:** برخلاف هاست اشتراکی، کانتینر Railway همیشه روشن می‌مونه (نمی‌خوابه)،
  پس همون ترد پس‌زمینه‌ی داخلی (`core/scheduler.py`) بدون هیچ تنظیم اضافه‌ای کاملاً قابل‌اعتماده.
- **دستور «ریستارت بات»:** روی Railway لمس‌کردن `tmp/restart.txt` اثری نداره (چون اونجا Passenger
  نیست)، ولی مشکلی هم پیش نمیاد — فقط اون فایل ساخته می‌شه و بی‌اثر می‌مونه. برای اعمال قابلیت جدید
  روی Railway، کافیه کد جدید رو push کنی به همون ریپوی گیت‌هاب؛ Railway خودش خودکار دوباره دیپلویش
  می‌کنه و اپ رو ری‌استارت می‌کنه (همین‌جوریش هم بهتر از اون دستوره).
- **لاگ‌ها:** از تب **Deployments** روی سرویس ربات، هر دیپلوی رو باز کن، لاگ‌های لحظه‌ای اپ
  (همون‌چیزی که تو `storage/php_errors.log` قبلاً می‌نوشتیم) رو مستقیم اونجا هم می‌بینی.
- **هزینه:** Railway یه مقدار اعتبار رایگان ماهانه می‌ده؛ برای یه ربات تلگرامی معمولی معمولاً کافیه،
  ولی اگه گروه‌های پرترافیک زیاد داری، مصرفش رو از تب Usage چک کن.

## روش‌های دیگر (VPS با SSH، یا هاست اشتراکی بدون SSH)

اگه از Railway استفاده می‌کنی، دیگه لازم نیست این بخش‌ها رو بخونی — بالا همه‌چیز گفته شد.
این پایین برای کسایی‌ه که VPS شخصی دارن یا می‌خوان رو هاست اشتراکی (بدون SSH) بالا بیارنش.

## ۱) نصب پیش‌نیازها
دو روش نصب پایین آمده: یکی برای وقتی سرور/VPS با SSH دارید، یکی برای هاست اشتراکی
بدون SSH (با پنلی مثل همینی که استفاده می‌کنید، از طریق گزینه‌ی «Setup Python App»).
اگر هاست اشتراکی دارید مستقیم بروید سراغ «نصب روی هاست اشتراکی (بدون SSH)» پایین‌تر.

```bash
pip install -r requirements.txt
```

## ۲) دیتابیس
یک دیتابیس MySQL بسازید و محتویات `install/table.sql` را در آن اجرا کنید (از phpMyAdmin یا مشابه؛
ساختار جدول‌ها دقیقاً همان نسخه‌ی PHP است، پس اگر قبلاً دیتابیس نسخه‌ی PHP را داشتید نیازی به تغییر نیست).
سپس در `config.py` بخش `db` را با اطلاعات دیتابیس‌تان پر کنید (host, name, user, pass).

## ۳) تنظیمات ربات
فایل `config.py` را باز کنید:
- `bot_token` و `bot_username` از قبل برای شما پر شده.
- `owners` را با آیدی عددی خودتان پر کنید (با @userinfobot بگیرید) تا به آمار و پیام همگانی دسترسی داشته باشید.
- `webhook_secret` را می‌توانید همان مقدار پیش‌فرض بگذارید یا تغییر بدهید.

## ۴) اجرا (پشت HTTPS) — روی VPS/سروری که SSH دارید
با Gunicorn اجرا کنید (پشت nginx/Apache به‌عنوان reverse proxy با گواهی SSL):
```bash
gunicorn -w 2 -b 127.0.0.1:8000 app:app
```
یا برای تست سریع محلی:
```bash
python3 app.py
```

## ۵) ثبت وبهوک
فایل `install/set_webhook.py` را باز کنید و مقدار `WEBHOOK_URL` را با آدرس عمومی و https اپ خودتان
جایگزین کنید، سپس یک‌بار اجرا کنید:
```bash
python3 install/set_webhook.py
```
پیام «✅ وبهوک با موفقیت ثبت شد» باید ببینید.

(اگر SSH ندارید و نمی‌توانید این اسکریپت را اجرا کنید، در بخش «نصب روی هاست اشتراکی» پایین‌تر
یک روش جایگزین بدون نیاز به اجرای اسکریپت — فقط با باز کردن یک لینک در مرورگر — توضیح داده شده.)

## ۶) کرون‌جاب — دیگر لازم نیست ✅
کارهای دوره‌ای (ارسال پیام همگانی و حذف خودکار پیام خوش‌آمد/خداحافظی) از این نسخه به بعد
**داخل خودِ اپ** و در یک ترد پس‌زمینه انجام می‌شوند — همین که `app.py` (یا Gunicorn) در حال اجراست،
این کارها هم خودکار هر ۱۰ ثانیه یک‌بار چک می‌شوند. نیازی به تنظیم Cron Job نیست.

اگر با چند worker اجرا کنید (مثلاً `gunicorn -w 4`)، مشکلی نیست — از یک قفل MySQL استفاده شده
تا در هر لحظه فقط یکی از worker ها واقعاً کار را انجام دهد.

اگر با این حال (مثلاً روی هاستی که پردازه‌ها را زنده نگه نمی‌دارد) ترجیح می‌دهید از کرون
جداگانه استفاده کنید، فایل `cron.py` هنوز موجود و کاملاً کاربردی است:
```
* * * * * /usr/bin/python3 /path/to/zandbot/cron.py >/dev/null 2>&1
```
اجرای هم‌زمان هر دو (ترد داخلی + کرون خارجی) هم مشکلی ندارد، چون هر دو از همان قفل استفاده می‌کنند.

## نصب روی هاست اشتراکی، بدون SSH (با «Setup Python App» در پنل)

این بخش مخصوص وقتیه که هاست اشتراکی دارید و به SSH دسترسی ندارید، ولی پنل هاستتان
(مثل تصویری که فرستادید) بخش «Setup Python App» را زیر «EXTRA FEATURES» دارد. همه‌ی
مراحل زیر فقط با کلیک داخل پنل و File Manager انجام می‌شود، بدون خط فرمان.

### گام ۱ — ساخت اپ پایتون
1. در پنل روی **Setup Python App** بزنید.
2. **Create Application** را بزنید.
3. **Python version**: جدیدترین نسخه‌ی موجود (۳.۹ به بالا) را انتخاب کنید.
4. **Application root**: یک نام پوشه بدهید، مثلاً `zandbot` (پنل آن را زیر پوشه‌ی دامنه‌تان می‌سازد).
5. **Application URL**: دامنه یا ساب‌دامنه‌ای که می‌خواهید وبهوک رویش باشد را انتخاب کنید
   (می‌توانید یک ساب‌دامنه‌ی جدید مثل `bot.ablshi.pouyan.it` بسازید، یا از دامنه‌ی اصلی یک مسیر مثل `/zandbot` استفاده کنید).
6. **Application startup file**: بنویسید `passenger_wsgi.py`
7. **Application Entry point**: بنویسید `application`
8. روی **Create** بزنید. پنل یک پوشه با یک `passenger_wsgi.py` نمونه و یک virtualenv می‌سازد.

### گام ۲ — آپلود فایل‌های پروژه
1. از پنل بروید به **File Manager**.
2. وارد همان پوشه‌ای شوید که در گام ۱ ساختید (Application root).
3. فایل زیپ پروژه (همینی که برایتان فرستاده شده) را در همان پوشه **Upload** کنید.
4. روی فایل زیپ راست‌کلیک (یا از منوی بالا) بزنید و **Extract** را انتخاب کنید تا محتوایش همان‌جا باز شود.
5. مطمئن شوید فایل‌هایی مثل `app.py`، `config.py`، `passenger_wsgi.py` مستقیم داخل همان پوشه‌ی اصلی
   هستند (نه داخل یک زیرپوشه‌ی اضافه به اسم zandbot/zandbot) — اگر داخل یک زیرپوشه رفتند،
   محتوایشان را انتخاب و به یک پوشه بالاتر Move کنید.
6. فایل `passenger_wsgi.py` که همراه پروژه آمده را نگه دارید (پنل هم یک نمونه‌ی خودش می‌سازد؛
   فایل خودِ ما را جایگزینش کنید — دقیقاً کاری که لازم است را انجام می‌دهد).

### گام ۳ — نصب کتابخانه‌ها (بدون ترمینال)
1. برگردید به صفحه‌ی **Setup Python App** و روی اپی که ساختید بزنید تا جزئیاتش باز شود.
2. یک بخش «Detected configuration files» یا کادر متنی برای نصب پکیج‌ها می‌بینید — مسیر
   `requirements.txt` را که در پوشه‌ی پروژه هست انتخاب/تایید کنید، یا روی دکمه‌ای مثل
   **Run Pip Install** بزنید (بسته به پنل، اسمش کمی فرق دارد ولی همیشه هست).
3. صبر کنید تا پیام موفقیت نصب پکیج‌ها (Flask، PyMySQL، requests) را ببینید.

### گام ۴ — دیتابیس
1. از پنل بروید به **Databases** (زیر ACCOUNT MANAGER) و یک دیتابیس MySQL بسازید (یا اگر از
   قبل دیتابیس نسخه‌ی PHP همین ربات را دارید، همان را نگه دارید — نیازی به ساخت جدید نیست).
2. از **phpMyAdmin** (زیر EXTRA FEATURES) وارد همان دیتابیس شوید، تب **SQL** را باز کنید،
   محتوای فایل `install/table.sql` را کپی‌پیست کنید و اجرا (Go) بزنید.
3. با File Manager فایل `config.py` را باز کنید (روی آن راست‌کلیک → **Edit** یا **Code Editor**)
   و بخش `db` را با نام دیتابیس، یوزر و پسورد واقعی‌ای که ساختید پر کنید. ذخیره کنید.

### گام ۵ — SSL و ری‌استارت اپ
1. مطمئن شوید همان دامنه/ساب‌دامنه‌ای که برای اپ انتخاب کردید گواهی SSL فعال دارد
   (از بخش **SSL Certificates** در پنل، اکثر هاست‌ها AutoSSL رایگان دارند).
2. برگردید به **Setup Python App** و روی دکمه‌ی **Restart** اپتان بزنید تا تغییرات
   (نصب پکیج‌ها، ویرایش config.py) اعمال شود.
3. آدرس اپ را در مرورگر باز کنید؛ اگر خطای 500 داخلی ندید (حتی یک صفحه‌ی خالی یا خطای
   404 برای متد GET طبیعی‌ست، چون فقط روی POST جواب می‌دهد) یعنی اپ بالاست.

### گام ۶ — ثبت وبهوک (بدون اجرای اسکریپت، فقط با یک لینک)
چون SSH ندارید، به‌جای اجرای `install/set_webhook.py`، همین آدرس را در مرورگر باز کنید
(به‌جای `<TOKEN>` توکن ربات از `config.py`، به‌جای `<APP_URL>` آدرس همان دامنه/ساب‌دامنه‌ای
که در گام ۱ انتخاب کردید، و به‌جای `<SECRET>` مقدار `webhook_secret` از `config.py` را بگذارید):

```
https://api.telegram.org/bot<TOKEN>/setWebhook?url=<APP_URL>&secret_token=<SECRET>
```

مثلاً چیزی شبیه این (فقط نمونه، مقادیر خودتان را بگذارید):
```
https://api.telegram.org/bot8680723464:AAGca2_GEFJhHAOHXvCjUo_5A1PXop7tEEc/setWebhook?url=https://bot.ablshi.pouyan.it/&secret_token=zand-shiraz-secret-2026
```

اگر در مرورگر جواب `{"ok":true,"result":true,"description":"Webhook was set"}` را دیدید،
یعنی وبهوک با موفقیت ثبت شد. همین.

### نکته درباره‌ی «کرون‌جاب» روی این نوع هاست
اپ‌های Python روی Passenger (همین نوع هاست) گاهی بعد از مدتی بی‌کاری خوابیده و با اولین
درخواست دوباره بیدار می‌شوند؛ در این حالت ترد پس‌زمینه‌ی داخلی (بخش ۶ بالا) هم موقتاً متوقف
می‌شود. برای اطمینان از این‌که پیام همگانی و حذف خودکار همیشه به‌موقع اجرا شوند، بهتر است
از همان بخش **Cron Jobs** در پنل (زیر ADVANCED FEATURES) یک کرون هم اضافه کنید — نیازی به
SSH ندارد، فقط داخل فرم پنل این را می‌نویسید (مسیر واقعی پوشه‌ی اپ و مسیر پایتونِ virtualenv
که پنل ساخته را از همان صفحه‌ی Setup Python App کپی کنید):

- **Minute**: `*/1` (هر ۱ دقیقه)
- **Command**:
```
/home/USERNAME/virtualenv/zandbot/3.x/bin/python /home/USERNAME/domains/DOMAIN/zandbot/cron.py
```
(این مسیر نمونه است؛ مسیر دقیق virtualenv را از بالای صفحه‌ی Setup Python App، جایی که
نوشته «Enter to the virtual environment»، کپی کنید — همان خط اول را داخل Command کرون بگذارید،
با `&&` به دستور `python cron.py` وصلش کنید.)

## ۷) اضافه کردن ربات به گروه
ربات را با دسترسی‌های ادمین (حذف پیام، محدودسازی اعضا، پین پیام، دعوت با لینک) به گروه اضافه کنید.
داخل گروه دستور `/panel` (یا معادل فارسی «پنل») را بزنید تا لینک پنل شیشه‌ای مدیریت باز شود.

## امکانات

**مدیریت اعضا:** `/ban` `/unban` `/kick` `/mute [10m|2h|1d]` `/unmute` `/warn` `/unwarn` `/warns`
`/promote` `/demote` — همه با ریپلای روی پیام فرد. همه‌ی این دستورات معادل فارسی هم دارند
(بن، آنبن، اخراج، سکوت، رفع_سکوت، اخطار، حذف_اخطار، اخطارها، ادمین، عزل) که بدون `/` هم کار می‌کنند.

**قفل‌ها (۱۹ نوع):** لینک، فوروارد، استیکر، گیف، عکس، ویدیو، صدا، ویدیو-پیام، موزیک، فایل،
مخاطب، لوکیشن، نظرسنجی، بازی، منشن، هشتگ، انگلیسی، متن، ریپلای — با `/lock نوع` `/unlock نوع`
یا از پنل شیشه‌ای (با صفحه‌ی تاییدیه‌ی کامل برای هر قفل).

**ضدفلود (Anti-Flood):** تعداد پیام مجاز در بازه‌ی زمانی قابل تنظیم، با سکوت خودکار برای اسپم‌کننده.

**فیلتر کلمات نامناسب:** `/addbadword` `/rembadword` `/badwords` + حذف خودکار و اخطار
(نیازمند فعال بودن «قفل فحش»).

**سیستم اخطار:** بعد از رسیدن به سقف اخطار، اکشن انتخابی (بن/سکوت/اخراج) خودکار اجرا می‌شود.

**خوش‌آمد و خداحافظی:** متن قابل‌شخصی‌سازی با متغیرهای {user} {inviter} {inviter_invites_count}
{group} {date} {time} {day_of_week} {month_name} {user_id} {username} {emoji}، رسانه (عکس/گیف)،
دکمه‌های سفارشی نامحدود، حذف خودکار با تایمر قابل تنظیم، و پیش‌نمایش زنده — همه از پنل.

**کپچای اعضای جدید:** عضو جدید تا لمس دکمه‌ی تاییدیه نمی‌تواند پیام بفرستد (ضدربات/ضداسپم).

**جوین اجباری (چندکاناله):** تا ۱۰ کانال، افزودن با یوزرنیم یا فوروارد پیام، بررسی خودکار عضویت.

**اد اجباری و محدودیت کاراکتر:** هر دو با کنترل پله‌ای از پنل.

**قوانین گروه:** `/setrules` و `/rules`، با دکمه‌ی نمایش در پیام خوش‌آمد.

**پنل شیشه‌ای مدیریت:** `/panel` داخل گروه → پنل کامل تنظیمات با دکمه در پی‌وی ربات، بدون نیاز
به حفظ‌کردن دستورات.

**راهنمای تعاملی:** `/help` یا «راهنما» — ویزارد دکمه‌ای کامل.

**سرگرمی:** فال حافظ (تصویری) و پخش زنده‌ی تلویزیون، از «سرگرمی».

**پیام همگانی (فقط مالک ربات):** `/broadcast` یا `/broadcastgroups` در پی‌وی ربات.

**آمار (فقط مالک ربات):** `/stats`

**ری‌استارت ربات (فقط مالک ربات):** با نوشتن «ریستارت بات» (تو گروه یا پی‌وی ربات) اپ خودش را
دوباره بالا می‌آورد تا هر فایل/قابلیت جدیدی که آپلود کرده‌اید فعال شود — بدون نیاز به SSH یا
رفتن تو پنل هاست. (فنی: یک فایل `tmp/restart.txt` را لمس می‌کند؛ این همان قرارداد استاندارد
Passenger است که هاست‌های اشتراکی با «Setup Python App» از آن استفاده می‌کنند. روی دیپلوی‌های
دیگر مثل systemd/Gunicorn معمولی، خودش اثری ندارد مگر یک watcher برایش تنظیم کرده باشید.)

لیست کامل دستورات هر لحظه با ارسال `/help` یا «راهنما» داخل گروه قابل مشاهده است.
